# PRD-008 - Sistema de Checkout

## Objetivo

Implementar o fluxo completo de checkout do e-commerce, permitindo que o cliente finalize uma compra a partir do carrinho.

Nesta etapa será realizada apenas a criação do pedido. O processamento do pagamento será implementado posteriormente.

---

# Stack do Projeto

## Frontend

* Next.js 15 (App Router)
* React 19
* TypeScript
* Tailwind CSS

## Backend

* NestJS
* Prisma ORM
* PostgreSQL

---

# Objetivos do Checkout

O checkout deverá permitir que o cliente:

* Informar seus dados pessoais
* Informar endereço de entrega
* Escolher método de entrega
* Visualizar resumo do pedido
* Confirmar a compra

Ao confirmar:

* Criar um pedido no banco
* Reservar (baixar) o estoque das variantes
* Redirecionar para a tela de confirmação

---

# Fluxo do Checkout

## Etapa 1

Identificação do cliente.

Caso esteja logado:

* Preencher automaticamente.

Caso não esteja:

* Permitir compra como visitante.

Campos:

* Nome
* Email
* Telefone

---

## Etapa 2

Endereço de entrega.

Campos:

* CEP
* Rua
* Número
* Complemento
* Bairro
* Cidade
* Estado
* País

Preparar integração futura com busca automática por CEP.

---

## Etapa 3

Entrega

Exibir opções de frete.

Nesta etapa utilizar dados simulados.

Exemplo:

* PAC
* SEDEX
* Retirada na Loja

---

## Etapa 4

Resumo

Exibir:

* Produtos
* Quantidades
* Valor dos itens
* Frete
* Descontos (futuro)
* Valor total

Botão:

"Finalizar Pedido"

---

# API

## Público

POST /checkout

Responsabilidades:

* Validar carrinho
* Validar estoque
* Criar pedido
* Criar itens
* Salvar endereço
* Atualizar estoque
* Retornar número do pedido

---

GET /orders/:orderNumber

Retorna detalhes do pedido.

---

# Página de Sucesso

Criar rota:

/pedido/sucesso

Exibir:

* Número do pedido
* Resumo da compra
* Produtos adquiridos
* Valor total
* Mensagem de agradecimento

---

# Regras de Negócio

Antes de criar o pedido:

* Validar estoque.
* Validar variantes.
* Validar produtos ativos.

Após criar:

* Reduzir estoque.
* Limpar carrinho.
* Gerar número único do pedido.

Caso algum item esteja indisponível:

* Cancelar toda a operação.

---

# Validações

* CEP obrigatório.
* Endereço obrigatório.
* Pelo menos um item no carrinho.
* Estoque suficiente.
* Email válido.
* Telefone válido.

---

# Estados do Pedido

Criar enum:

* PENDING
* WAITING_PAYMENT
* PAID
* PROCESSING
* SHIPPED
* DELIVERED
* CANCELLED
* REFUNDED

Nesta etapa o pedido será criado como:

WAITING_PAYMENT

---

# Requisitos Técnicos

* Utilizar transações do Prisma.
* Todo o checkout deve ocorrer dentro de uma única transação.
* Caso qualquer etapa falhe, desfazer toda a operação.
* DTOs separados.
* Tipagem completa.
* Código organizado por feature.

---

# Segurança

* Validar todas as entradas.
* Não confiar em valores enviados pelo frontend.
* Recalcular todos os preços no backend.
* Validar novamente o estoque.
* Nunca utilizar preços enviados pelo cliente.

# Critérios de Aceitação

* Cliente consegue finalizar um pedido.
* O pedido é salvo corretamente.
* O endereço é salvo.
* Os itens são registrados.
* O estoque é atualizado.
* O carrinho é limpo após a compra.
* É exibida uma página de sucesso.
* O sistema impede pedidos com estoque insuficiente.
* Todo o processo é executado dentro de uma transação do banco de dados.
